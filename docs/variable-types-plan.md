# Variable Types Simulation Plan

This document defines what each `VariableModel.valueType` should mean in simulation. The current target is pragmatic SCM behavior: each node remains a variable with a structural mechanism, and value type controls output domain, default distributions, override coercion, and eventually measurement/intervention behavior.

## Current Baseline

Implemented:

- `binary`
  - Root default: `Bernoulli(p=0.5)`.
  - Non-root default: `bernoulli_logit` combiner.
  - Overrides coerce to `0` or `1`.
  - `single_draw` samples `0/1`.
  - `expected_value` returns probability.
- Per-node distribution state
  - `SimulationResult.values` remains the scalar projection used by existing edge mechanisms.
  - `SimulationResult.nodeStates` now carries analytic and empirical distribution summaries.
  - Analytic summaries are available for root distributions and additive linear SEM nodes where a moment-matched normal distribution can be derived.
  - Empirical summaries are simulated for every node from repeated seeded draws.

Still mostly metadata:

- Measurement model.
- Intervention semantics beyond manual override.
- Population and uncertainty display modes.
- Observed-vs-latent value separation.

## General Rules

Each variable type should define:

- Domain: valid values.
- Root defaults: default distribution and parameter controls.
- Non-root defaults: default combiner/link and post-processing.
- Override behavior: coercion or validation.
- Display behavior: how values are shown in `single_draw`, `expected_value`, and future population modes.
- Measurement behavior: how true values become observed values.

Simulation should eventually return more than one value per node:

```ts
{
  latent?: number | string | number[];
  trueValue: number | string | number[];
  observed?: number | string | number[] | null;
  expectation?: number | number[];
  probability?: number | Record<string, number>;
}
```

For now, `SimulationResult.values` remains numeric, so non-scalar types need a staged implementation.

## Type Plans

### Continuous

Meaning: unconstrained real scalar.

Near-term implementation:

- Root default: `normal(mean=0, sd=1)`.
- Non-root default: `additive`.
- Overrides: accept any finite number.
- Output: real number.

Current status:

- Effectively implemented by existing default scalar simulation, except root defaults are still often constant.

Next steps:

- When type changes to `continuous`, optionally set root distribution to normal if the previous type had a constrained distribution.
- Keep this as the base case for most SEMs.

Reference example:

- The built-in Galton regression-to-the-mean example models father and son height as continuous normal variables generated by shared latent genetics plus independent latent factors.
- It deliberately has no `Father_height -> Son_height` causal edge. Father height predicts son height because it is a noisy observation of shared latent causes.
- The visual north star is that each node shows both analytic distribution information, when derivable, and an empirical histogram from repeated simulation.

### Distributional

Meaning: a node whose displayed state is primarily a distribution rather than a single scalar draw.

Implemented first pass:

- `distributional` is an allowed `VariableModel.valueType`.
- Root distributional nodes default to a normal root distribution when switched from a constant root.
- The simulator exposes `nodeStates[id].analytic` and `nodeStates[id].empirical` for all nodes, not just `distributional` nodes.
- The graph still uses `values[id]` as a scalar projection so existing edge functions remain compatible.

Current semantic rule:

- Analytic distribution available:
  - root node: configured root distribution
  - additive linear non-root node: derived or moment-matched normal distribution
- Empirical distribution:
  - repeated seeded forward simulations through the graph
  - always available when the enabled directed graph is acyclic

Next steps:

1. Distinguish true distribution-valued variables from ordinary scalar random variables.
2. Add explicit projection choices: mean, draw, quantile, probability-above-threshold.
3. Add distribution-to-distribution edge mechanisms.
4. Track covariance for shared-parent linear Gaussian SEMs.
5. Add empirical uncertainty bands for nonlinear and neural mechanisms where analytic propagation is unavailable.

### Binary

Meaning: two-state variable encoded as `0` or `1`.

Implemented:

- Root default: Bernoulli.
- Non-root default: Bernoulli-logit.
- Override coercion.
- Expected-value mode returns probability.

Next steps:

- Add a toggle control instead of a slider in the simulation row.
- Show both draw and probability when useful.
- Add observed misclassification via measurement model.

### Categorical

Meaning: unordered finite set with more than two levels.

Near-term implementation:

- Root default: categorical probabilities over `categories`.
- Non-root default: multinomial-logit/softmax over categories.
- Overrides: choose one category.
- Numeric compatibility: store selected category index in `values` until `SimulationResult` supports non-numeric values.

Required model additions:

- Add a categorical distribution:
  - `{ kind: "categorical"; categories: string[]; probabilities: number[] }`
- Add a node combiner/output family:
  - `categorical_softmax`
  - Later: per-category linear predictors.

Implementation stages:

1. UI-only plus override dropdown.
2. Root categorical sampling using index encoding.
3. Non-root softmax with simple shared score or per-category intercepts.
4. Result model supports string category values.

### Ordinal

Meaning: ordered finite levels.

Near-term implementation:

- Root default: categorical probabilities over ordered categories.
- Non-root default: ordered-logit/probit threshold model.
- Overrides: choose one ordered level.
- Numeric compatibility: encode as level index.

Required model additions:

- Ordered thresholds on the node mechanism.
- Possibly `ordinal_logit` combiner.

Implementation stages:

1. Treat as categorical with order metadata.
2. Add ordered-logit thresholds.
3. Add monotonic parent effects and threshold editing.

### Count

Meaning: nonnegative integer.

Near-term implementation:

- Root default: `poisson(lambda=1)`.
- Non-root default: `poisson_log`.
- Overrides: round and clamp to integer `>= 0`.
- Expected-value mode: return rate/mean.
- Single-draw mode: sample Poisson from rate.

Already available:

- Poisson distribution exists.
- `poisson_log` combiner exists.

Next steps:

- Implement type-driven defaults and override coercion.
- Add final sampling for non-root count variables.
- Add negative-binomial later for overdispersion.

### Positive

Meaning: positive real scalar.

Near-term implementation:

- Root default: `lognormal` or `gamma`.
- Non-root default: `gamma_log` or `positive_softplus`.
- Overrides: clamp to `> 0`.
- Expected-value mode: return positive mean.

Already available:

- Lognormal and gamma distributions exist.
- `positive_softplus` and `gamma_log` exist.

Next steps:

- Implement type-driven defaults.
- Decide whether `positive` should sample gamma/lognormal or just transform a latent score.
- Add lower bound epsilon in override coercion.

### Proportion

Meaning: scalar in `[0, 1]`.

Near-term implementation:

- Root default: `beta(alpha=2, beta=2)`.
- Non-root default: `bounded_logistic`.
- Overrides: clamp to `[0, 1]`.
- Expected-value mode: return probability/proportion.

Already available:

- Beta distribution exists.
- `bounded_logistic` exists.

Next steps:

- Implement defaults and coercion.
- Add beta regression-style precision parameter later:
  - mean from structural equation
  - concentration/precision controls variance

### Time To Event

Meaning: nonnegative duration until event.

Near-term implementation:

- Root default: `exponential(rate=1)`.
- Non-root default: hazard/rate model with log link.
- Overrides: clamp to `>= 0`.
- Expected-value mode: return expected time or hazard, but this must be explicit.

Required model additions:

- Distinguish simulated time from hazard/rate.
- Add event/censoring fields.
- Measurement model should support right-censoring.

Implementation stages:

1. Root exponential sampling and nonnegative coercion.
2. Non-root `hazard_log` combiner returns rate.
3. Sample event time from rate.
4. Add censoring and survival display.

### Vector

Meaning: fixed-length numeric vector.

Near-term implementation:

- Keep as metadata until `SimulationResult` supports vector values.
- UI should allow dimensionality and labels.
- Graph display can show summary norm or selected component.

Required model additions:

- Vector-valued distributions.
- Vector operations in mechanisms.
- Result value type expansion.

Implementation stages:

1. Metadata fields: dimension, component labels.
2. Store vector values in `SimulationResult`.
3. Add linear map edge mechanisms.
4. Add per-component visualization.

### Time Series

Meaning: sequence indexed by time.

Near-term implementation:

- Keep as metadata until simulation has a temporal engine.
- UI should allow time index, horizon, and step size.
- Graph display can show current time slice.

Required model additions:

- Dynamic structural equations.
- Lagged parent references.
- Time-indexed interventions.

Implementation stages:

1. Metadata: horizon, step, lag support.
2. Simulate a fixed horizon in topological order per time step.
3. Add lag edges and temporal plots.
4. Support policy interventions over time.

### Text

Meaning: string-valued observation.

Near-term implementation:

- Metadata only.
- Useful for naming real-world variables and future learned mechanisms.

Future implementation:

- Categorical/text generation via external model.
- Embedding projection for downstream mechanisms.
- Measurement model as annotation/coding process.

Implementation stages:

1. Metadata only.
2. Allow text root samples from enumerated values.
3. Connect to embedding variable or external model.

### Embedding

Meaning: numeric vector representation of text/image/high-dimensional object.

Near-term implementation:

- Metadata only, like vector.

Future implementation:

- Store vector dimension and normalization.
- Use vector mechanisms, learned mappings, or neural networks.
- Show scalar projections in graph view.

Implementation stages:

1. Metadata: dimension, source modality.
2. Vector-valued result support.
3. Learned mechanism backend.
4. Projection and similarity visualizations.

## Cross-Cutting Work

### Simulation Result Shape

The current `values: Record<string, number>` is now treated as the scalar projection used for graph labels and existing edge mechanisms. Richer distribution state lives beside it.

Current shape:

1. Keep numeric `values` for graph labels and backwards compatibility.
2. Use `nodeStates: Record<string, SimulatedNodeState>` for analytic and empirical distribution summaries.
3. Keep observed-vs-true values minimal for now: `observed` mirrors the scalar value until measurement models are implemented.

Remaining work:

1. Add non-numeric state payloads for categorical, text, vector, and time-series nodes.
2. Add covariance/joint summaries for models like Galton where marginal distributions are analytic but conditional prediction depends on shared latent causes.
3. Gradually migrate panels from `values` to `nodeStates`.

### Type-Driven Defaults

Implemented for binary only.

Next candidates:

1. Count.
2. Proportion.
3. Positive.
4. Continuous root defaults.
5. Time-to-event root defaults.

### Type-Driven Override Controls

Current controls are numeric.

Plan:

- Binary: toggle.
- Categorical/ordinal: dropdown.
- Count: integer stepper.
- Proportion: slider `[0, 1]`.
- Positive/time-to-event: nonnegative number input.
- Vector/time-series: modal/detail editor.

### Measurement Model

Measurement should not mutate the structural value directly. The simulator should eventually produce:

- latent or true variable value
- observed value
- missingness/censoring flag

First measurement implementations:

1. Missing-prone: observed is `null` with probability `missingRate`.
2. Noisy proxy: observed = true value + measurement noise.
3. Binary misclassification.
4. Censoring for time-to-event.

### Intervention Semantics

Manual override is currently the closest implemented behavior to a hard intervention. It replaces the node's structural assignment for the current simulation draw and downstream propagation follows outgoing causal edges only.

Implemented first pass:

- `SimulationSpec.overrides`
  - hard/manual setting of a node value
  - example: putting the father on stilts changes `Father_height`, but does not change `Son_height` in the Galton graph because there is no causal edge from father height to son height
- `SimulationSpec.selections`
  - observational conditioning/filtering of empirical Monte Carlo samples
  - example: selecting samples where `Father_height >= 72` shifts the empirical distribution of `Son_height` upward because tall fathers are enriched for shared latent height causes
  - each condition has a sampling mode:
    - `auto`: use importance sampling when supported, otherwise rejection
    - `importance`: request likelihood-weighted proposal sampling
    - `rejection`: force prior forward sampling plus filtering
- `SimulationResult.conditioning`
  - reports accepted sample count, total attempted samples, and active conditioning predicates
  - reports when analytic linear-Gaussian conditioning was applied
  - reports empirical method and effective sample size

Analytic conditioning implemented:

- Eligibility:
  - all active directed edges are linear
  - all node combiners are additive
  - no interaction terms
  - all root distributions and non-root noise terms are normal or constant
  - variable types are continuous or distributional
- Method:
  - compute the joint mean vector and covariance matrix in topological order
  - for one active selection condition, update each node's analytic moments using Gaussian conditioning/truncated-normal formulas
  - equality-like `between` conditions with equal bounds use exact Gaussian conditioning
  - one-sided and interval selections use moment-matched normal summaries, because the selected marginal is generally not exactly normal
- Galton check:
  - `Father_height >= 72` gives `E[Son_height | Father_height >= 72]` about `70.6`
  - `Father_height = 78` as a manual override does not change `Son_height` unless a causal path exists

Empirical conditioning methods:

- Forward rejection sampling
  - Draw complete worlds from the prior SEM, keep only worlds satisfying the selection filter.
  - Works for common events and simple sanity checks.
  - Fails for extreme percentiles because almost every simulated world is discarded.
- Likelihood-weighted importance sampling
  - Implemented first pass for continuous/distributional nodes whose selected value is generated by a normal root distribution or additive normal node noise.
  - At a selected node, draw the root/noise term from its distribution conditional on the selection interval, then weight the whole world by the probability of that selection under its parent context.
  - This is much more efficient for rare conditions on noisy intermediate variables.
  - `SimulationResult.conditioning.empiricalMethod` reports `importance`, and `effectiveSampleSize` reports weight degeneracy.
  - The UI exposes this as a sampling menu on the conditioning filter.
- Kernel/ABC conditioning
  - Future fallback for equality-like continuous evidence where exact equality has probability zero.
  - Replace hard equality with a likelihood kernel such as `Normal(observed; simulated, bandwidth)`.
  - Useful for noisy observations and measurement models.
- Sequential Monte Carlo
  - Future method for multiple intermediate conditions.
  - Simulate particles forward, reweight/resample at each conditioned node, then continue to descendants.
  - Better than final rejection when conditions appear early or midway through the graph.
- Laplace/local Gaussian proposals
  - Future method for differentiable nonlinear SEMs.
  - Optimize latent/root/noise values that satisfy evidence, approximate the posterior around the optimum, and sample from that proposal with importance weights.
- MCMC in exogenous-noise space
  - Future general fallback for hard nonlinear, deterministic, or rare-event conditions.
  - Sample root/noise terms, deterministically evaluate the graph, and accept/reweight based on evidence likelihood.
- Specialized exact inference
  - Future method for discrete Bayesian-network fragments, conjugate exponential-family fragments, and other recognizable model families.
  - Prefer exact or semi-exact inference whenever detection is reliable.

Plan:

1. Keep manual override as user interaction state.
2. Promote hard `do`: replace structural assignment and mark incoming edges inactive for intervention semantics.
3. Add soft shift: add shift to latent score or mean.
4. Add stochastic intervention: replace root/noise distribution.
5. Add policy intervention: value is a function of parent/context variables.
6. Extend analytic conditioning beyond one condition, using multivariate truncated-normal approximations or exact formulas where tractable.

## Recommended Next Implementation Order

1. Count
   - Poisson root default, Poisson-log non-root default, integer coercion.
2. Proportion
   - Beta root default, bounded-logistic non-root default, `[0, 1]` coercion.
3. Positive
   - Lognormal/gamma root default, positive-softplus/gamma-log non-root default, positive coercion.
4. Continuous cleanup
   - Normal root default when explicitly selected as continuous.
5. Categorical
   - Root categorical sampling with index encoding.
6. Ordinal
   - Ordered-logit thresholds.
7. Measurement model first pass
   - Missing-prone and noisy proxy.
8. Extend `SimulationResult.nodeStates`
   - Unlock non-numeric values, observed-vs-true displays, and joint/covariance summaries.
